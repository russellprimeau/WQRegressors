# Model Architectures

This document describes the four regression model types supported by `src/e_Train.py`,
with architectures parameterised by the default configuration templates generated by
`src/d_RunResample.py`.  The target application is probabilistic water-quality
forecasting from multi-sensor time-series windows.

---

## Problem Setup

Each training sample is a fixed-length window of multivariate sensor readings
(e.g. 168 hourly rows × $d$ sensor columns), and the regression target is a
scalar (or small vector) taken from the final row of that window.  Formally,
let $\mathbf{X} \in \mathbb{R}^{T \times d}$ be the input window and
$y \in \mathbb{R}$ the target.

All models are trained with a **70/30 temporal train/test split** to prevent
future data leaking into training.

---

## 1. Gaussian Process Regressor (`gp_regressor`)

### Overview

A Gaussian Process defines a distribution over functions.  Given training data
$\mathcal{D} = \{(\mathbf{x}_i, y_i)\}_{i=1}^{n}$, the predictive posterior at
a new point $\mathbf{x}_*$ is:

$$p(y_* \mid \mathbf{x}_*, \mathcal{D}) = \mathcal{N}(\mu_*, \sigma_*^2)$$

$$\mu_* = \mathbf{k}_*^\top (\mathbf{K} + \sigma_n^2 \mathbf{I})^{-1} \mathbf{y}$$

$$\sigma_*^2 = k(\mathbf{x}_*, \mathbf{x}_*) - \mathbf{k}_*^\top (\mathbf{K} + \sigma_n^2 \mathbf{I})^{-1} \mathbf{k}_*$$

where $\mathbf{K}_{ij} = k(\mathbf{x}_i, \mathbf{x}_j)$ and $\sigma_n^2$ is the
observation noise variance.  The GP is implemented via
[GPyTorch](https://gpytorch.ai/) (`ExactGPRegressor`), which uses an exact
Cholesky solver — tractable here because the training set is capped at
`max_train_size = 5000` samples to control $O(n^3)$ cost.

### Mean and Likelihood

- **Mean function:** constant mean $\mu(\mathbf{x}) = c$, learned jointly with
  the kernel hyperparameters.
- **Likelihood:** Gaussian observation noise
  $y = f(\mathbf{x}) + \varepsilon$, $\varepsilon \sim \mathcal{N}(0, \sigma_n^2)$,
  with $\sigma_n^2$ constrained to $[10^{-5},\, 1.0]$ and a
  $\text{Gamma}(1.5, 0.5)$ prior.

### Kernel

The selected kernel is `matern52+linear`, composed as:

$$k(\mathbf{x}, \mathbf{x}') = \sigma_f^2\, k_{\text{Matérn52}}(\mathbf{x}, \mathbf{x}') + k_{\text{linear}}(\mathbf{x}, \mathbf{x}')$$

where $\sigma_f^2$ is an output scale with a $\text{Gamma}(2.0, 0.15)$ prior.

#### Matérn-5/2 kernel (standard form)

$$k_{\text{Matérn52}}(\mathbf{x}, \mathbf{x}') = \left(1 + \sqrt{5}\,r + \frac{5}{3}r^2\right) e^{-\sqrt{5}\,r}$$

where $r = \sqrt{(\mathbf{x}-\mathbf{x}')^\top \boldsymbol{\Lambda}^{-2} (\mathbf{x}-\mathbf{x}')}$
and $\boldsymbol{\Lambda} = \text{diag}(\ell_1, \ldots, \ell_d)$ is the ARD
lengthscale matrix.

<!-- This kernel is **twice differentiable** — smooth enough to capture the gradual
diurnal cycles in water-quality signals, while still allowing sharp transitions
(unlike the infinitely smooth RBF) that reflect rapid storm events or tidal
flushing. -->

#### Uncertain-input Matérn-5/2 kernel (default, `use_uncertain_input_kernel = True`)

Sensor calibration uncertainty means each feature $x_j$ is measured with
additive noise $\varepsilon_j \sim \mathcal{N}(0, \sigma_j^2)$.  Rather than
ignoring this, the kernel expectation is approximated by Monte Carlo:

$$k_{\text{UI}}(\mathbf{x}_1, \mathbf{x}_2) \approx \frac{1}{S}\sum_{s=1}^{S} k_{\text{Matérn52}}\!\left(\mathbf{x}_1 + \boldsymbol{\delta}_s,\; \mathbf{x}_2 + \boldsymbol{\delta}_s\right)$$

where $\boldsymbol{\delta}_s \sim \mathcal{N}(\mathbf{0}, 2\boldsymbol{\Sigma})$
and $\boldsymbol{\Sigma} = \text{diag}(\sigma_1^2, \ldots, \sigma_d^2)$ encodes
per-sensor calibration variance.  The default uses $S = 64$ Monte Carlo samples
(`uncertain_kernel_mc_samples = 64`) with a fixed seed for reproducibility.
The per-sensor variance $\sigma_j^2$ is derived from aggregate calibration
offsets fitted to a Student's $t$ distribution (`uncertainty_source_mode = aggregate_t`).

The linear additive term captures any long-run monotone trends (e.g. gradual
sensor drift between calibrations) that stationary kernels alone cannot represent.

#### ARD lengthscales

With `ard = True`, each of the $d$ input dimensions has its own lengthscale
$\ell_j \in [0.05,\, 10.0]$, allowing the model to identify which sensor
channels are most informative for each target.

### Objective

Kernel hyperparameters, the output scale, the mean constant, and the noise
variance are all optimised jointly by maximising the **exact log marginal
likelihood** (type-II maximum likelihood):

$$\mathcal{L}_{\text{GP}} = \log p(\mathbf{y} \mid \mathbf{X}) = -\frac{1}{2}\mathbf{y}^\top \tilde{\mathbf{K}}^{-1} \mathbf{y} - \frac{1}{2}\log|\tilde{\mathbf{K}}| - \frac{n}{2}\log 2\pi$$

where $\tilde{\mathbf{K}} = \mathbf{K} + \sigma_n^2 \mathbf{I}$.  The first
term penalises poor data fit; the second penalises model complexity (large
determinant = broad prior); priors on the output scale and noise act as
additional regularisers via their log-density contributions to the gradient.

### Training

Optimiser: **Adam**, $\eta = 0.01$, up to 250 epochs, with patience 20 on
internal cross-validation RMSE (default `early_stop_source = cv`, 3 folds).
Features and targets are $z$-score standardised before fitting.

## 2. Transformer (`transformer`)

### Overview

The Transformer encoder processes the input window as a sequence of $T =
\text{sample\_length} - 1$ timesteps (rows `0` through `sample_length - 2`; the
final row is held out as the prediction target and is not part of the input).
The architecture is a standard **bidirectional encoder**: no causal mask is
applied, so every timestep attends to every other timestep in the window.

Two practical consequences follow from this design:

1. **The last-position readout is a convention, not a structural advantage.**
   The output projection is applied to the encoding of the last token
   (`encoded[:, -1, :]`), but because attention is bidirectional, every token's
   representation already aggregates information from the full window.  Mean-
   pooling across all positions would have equivalent representational capacity.

2. **The model functions as a fixed-context feature extractor, not an
   autoregressive predictor.**  The full observed window is available at inference
   time, so the bidirectional design is appropriate — the lack of causal masking
   is not a limitation here.  However, the claimed advantage of attention over
   simpler aggregations (e.g. mean-pooling or MLP on flattened input) depends
   entirely on whether the small training sets are sufficient to learn
   position-sensitive interaction patterns.

### Architecture

| Component | Default |
|---|---|
| Input projection | Linear $\mathbb{R}^d \to \mathbb{R}^{D}$ |
| Positional encoding | Learned, $\mathbb{R}^{T \times D}$ |
| Encoder layers | 2 |
| Model dimension $D$ | 64 |
| Attention heads | 4 |
| Dropout | 0.1 |
| Output projection | Linear $\mathbb{R}^{D} \to \mathbb{R}^1$ (applied to last token) |

Each encoder layer applies full (non-causal) self-attention:

$$\text{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{D/H}}\right)\mathbf{V}$$

followed by a position-wise feed-forward sublayer and layer normalisation.

Dropout is applied inside each encoder layer at $p = 0.1$ to regularise the
relatively small dataset sizes common in water-quality monitoring.

### Objective

Training minimises a composite loss combining MSE with a Pearson correlation
penalty to encourage directionally correct predictions:

$$\mathcal{L} = \mathcal{L}_{\text{MSE}} - \lambda_{\text{corr}}\, \rho(\hat{y}, y)$$

$$\rho(\hat{y}, y) = \frac{\sum_i (\hat{y}_i - \bar{\hat{y}})(y_i - \bar{y})}{\sqrt{\sum_i (\hat{y}_i - \bar{\hat{y}})^2 + \varepsilon}\;\sqrt{\sum_i (y_i - \bar{y})^2 + \varepsilon}}$$

Default: $\lambda_{\text{corr}} = 0.1$, $\varepsilon = 10^{-8}$ (clipped to
$[-1, 1]$).  The correlation term directly penalises models that achieve low
absolute error but fail to track relative changes — important for anomaly
detection in sensor streams.

### Training

Optimiser: **Adam**, $\eta = 0.001$, batch size 32, up to 100 epochs with
patience 10 on validation combined loss (default `early_stop_source = cv`,
3 folds, so no test-set exposure during training).

## 3. XGBoost Regressor (`xgb_regressor`) and Classifier (`xgb_classifier`)

### Overview

XGBoost trains an ensemble of $M$ decision trees (gradient boosted) where each
successive tree fits the negative gradient of the loss with respect to the
current ensemble prediction.  The final prediction is:

$$\hat{y} = \sum_{m=1}^{M} f_m(\mathbf{x})$$

where each $f_m$ is a regression tree.  XGBoost adds L1 and L2 regularisation
on the leaf weights to the standard CART objective:

$$\mathcal{L}^{(m)} = \sum_i \ell(y_i, \hat{y}_i^{(m-1)} + f_m(\mathbf{x}_i)) + \Omega(f_m)$$

$$\Omega(f) = \gamma T + \frac{1}{2}\lambda \sum_{j=1}^T w_j^2 + \alpha \sum_{j=1}^T |w_j|$$

where $T$ is the number of leaves and $w_j$ are leaf scores.

### Objective

At each boosting round $m$, the per-sample loss $\ell$ depends on the task:

| Variant | Loss $\ell(y,\hat{y})$ |
|---|---|
| Regressor (`reg:squarederror`) | $\dfrac{1}{2}(y - \hat{y})^2$ |
| Classifier (`binary:logistic`) | $-\bigl[y \log \hat{p} + (1-y)\log(1-\hat{p})\bigr]$ |

The classifier outputs the probability $\hat{p} = \sigma(\hat{y})$ of exceeding
a water-quality threshold (sigmoid applied to the raw score).

The regularisation term $\Omega(f)$ penalises tree complexity: $\gamma$ controls
the minimum gain required to add a leaf (pruning), $\lambda$ is L2 weight decay
on leaf scores, and $\alpha$ is L1 sparsity on leaf scores.

### Architecture Parameters (defaults)

| Hyperparameter | Regressor default | Classifier default |
|---|---|---|
| `n_estimators` | 1100 | 1100 |
| `max_depth` | 7 | 7 |
| `learning_rate` ($\eta$) | 0.01 | 0.01 |
| `subsample` | 0.2 | 0.2 |
| `colsample_bytree` | 0.8 | 0.8 |
| `min_child_weight` | 1 | 1 |
| `gamma` $(\gamma)$ | 0 | 0 |
| `reg_lambda` ($\lambda$) | 1 | 1 |
| `reg_alpha` ($\alpha$) | 0 | 0 |
| `tree_method` | `hist` | `hist` |
| Early stopping | 200 rounds (cv) | 50 rounds (cv) |

Key design choices:

- **Low subsample (0.2):** stochastic subsampling of training rows per tree
  provides strong regularisation and reduces overfitting on the small dataset
  sizes typical of multi-season water-quality records.
- **Deep trees (`max_depth = 7`):** allows the model to capture high-order
  sensor interactions (e.g. dissolved oxygen × temperature × conductivity)
  that are common in eutrophication dynamics.
- **Low learning rate with many estimators:** the combination
  $\eta = 0.01$ × 1100 rounds follows the well-known shrinkage principle —
  each tree contributes a small increment, reducing variance without sacrificing
  bias.  Early stopping (on internal CV to avoid test-set leakage) selects the
  optimal round count.
- **`hist` tree method:** histogram-based split finding reduces the
  $O(n \cdot d)$ per-level cost to $O(b \cdot d)$ where $b$ is the bin count
  (default 256, reduced to 64 during GPU CV tuning to limit QuantileDMatrix
  memory).

The input is the **flattened window** $\mathbf{X} \in \mathbb{R}^{T \times d}$
treated as a $Td$-dimensional feature vector.  Unlike the Transformer, XGBoost
does not encode the temporal ordering of rows explicitly; instead, position is
encoded implicitly by the distinct column indices at each timestep in the
flattened vector.

### Optional Hyperparameter Tuning

When `cv_tuning.enabled = True`, Optuna (TPE sampler, 10 startup trials) runs
up to 250 trials of 5-fold cross-validation on the training set, searching over
`n_estimators`, `max_depth`, `min_child_weight`, `gamma`, `subsample`,
`colsample_bytree`, `reg_lambda`, `reg_alpha`, and `learning_rate`.  The
**1-SE rule** (`selection_rule = "1se"`) selects the simplest model within one
standard error of the best cross-validated score, trading a small accuracy loss
for reduced overfitting.

## 4. Multiple Linear Regression with Feature Selection (`mlr`)

### Overview

MLR is a baseline and interpretability reference model.  It predicts the target
from a single aggregated predictor vector $\mathbf{x} \in \mathbb{R}^p$
extracted from the input window using one of three aggregation strategies:

| Variant | `aggregation_mode` | Description |
|---|---|---|
| `mlr` | `last` | Latest (last) row only |
| `mlr_avg12` | `avg12` | `nanmean` of last 12 rows |
| `mlr_avgall` | `avgall` | `nanmean` of all rows |

The `avg12` variant averages roughly the last 12 hours (for hourly data),
capturing short-window mean state; `avgall` represents the window-mean baseline.
The `last` variant is purely instantaneous and most comparable to a single-point
sensor reading.

### Feature Selection Pipeline

To avoid multicollinearity and overfitting on the typically small training sets
($n \sim 100$–$500$), a sequential feature selection pipeline is applied
**to training data only**:

1. **Spearman pre-filter:** retain base features where Spearman rank correlation
   $|\rho| > 0.20$ and $p < 0.05$ against the target.  This non-parametric
   filter is appropriate because sensor data often contains outliers and
   non-normal marginals.

2. **Constant feature removal:** drop any feature with zero variance across
   finite training samples.

3. **Mutual information filter:** drop features below the 10th percentile of
   $\hat{I}(X_j;\, y)$ estimated by $k$-nearest-neighbour regression.  MI
   captures non-linear associations that Spearman may miss for highly skewed
   distributions.

4. **Lasso / L1 regularisation:** fit LassoCV ($\ell_1$ path, 5-fold CV) and
   retain features with non-zero coefficients.  This simultaneously performs
   variable selection and estimating the regularisation level $\alpha^*$:

   $$\min_{\boldsymbol{\beta}} \frac{1}{2n}\|\mathbf{y} - \mathbf{X}\boldsymbol{\beta}\|_2^2 + \alpha^* \|\boldsymbol{\beta}\|_1$$

5. **Near-duplicate removal:** drop features with pairwise correlation
   $|\rho_{jk}| > 0.9999$, keeping the one with higher absolute target correlation.

6. **Variance Inflation Factor filter:** iteratively remove the feature with the
   highest VIF until all VIF $\leq 10$:

   $$\text{VIF}_j = \frac{1}{1 - R_j^2}$$

   where $R_j^2$ is from regressing feature $j$ on all remaining features.
   VIF $> 10$ indicates strong multicollinearity ($\sqrt{\text{VIF}} > 3.2$
   inflation of standard error), which would destabilise the OLS coefficient
   estimates.

### Objective

Two objectives are used in sequence.  Feature selection uses the **Lasso** (L1-penalised least squares), solved via coordinate descent with CV-tuned $\alpha^*$:

$$\mathcal{L}_{\text{Lasso}} = \frac{1}{2n}\|\mathbf{y} - \mathbf{X}\boldsymbol{\beta}\|_2^2 + \alpha^* \|\boldsymbol{\beta}\|_1$$

The final model is fitted by **ordinary least squares** on the selected feature
subset $\mathcal{S}$, which minimises the residual sum of squares without
regularisation:

$$\mathcal{L}_{\text{OLS}} = \|\mathbf{y} - \mathbf{X}_{\mathcal{S}}\boldsymbol{\beta}\|_2^2$$

with closed-form solution $\hat{\boldsymbol{\beta}} = (\mathbf{X}_{\mathcal{S}}^\top \mathbf{X}_{\mathcal{S}})^{-1} \mathbf{X}_{\mathcal{S}}^\top \mathbf{y}$.

### Refitting

After Lasso selects the feature subset, the final model is refitted via OLS on
those features.  Refitting without L1 penalty removes the shrinkage bias of
Lasso coefficients, giving unbiased estimates for the selected features.  This
two-step procedure is sometimes called the "relaxed Lasso" or "post-selection
inference" framework.

### Fallback Behaviour

If no features survive selection (e.g. very few training samples or all features
are NaN), MLR falls back to an **intercept-only** model predicting the training
mean for all test points.  This ensures that the baseline always produces a
finite prediction that downstream metrics can compare against.

## Summary Comparison

| Property | GP | Transformer | XGBoost | MLR |
|---|---|---|---|---|
| Training objective | Log marginal likelihood | MSE − $\lambda_{\text{corr}}\,\rho$ | Squared error / log-loss + $\Omega$ | Lasso (selection) then OLS (fit) |
| Temporal structure | Implicit (flattened) | Bidirectional attention over full window; last-token readout | Implicit (flattened) | Aggregated (single row or mean) |
| Uncertainty output | Calibrated posterior $\sigma_*^2$ | No | No | No |
| Handles sensor noise | Yes (uncertain-input kernel) | No | Partial (subsample) | No |
| Non-linearity | Kernel-induced | Multi-head attention + FFN | Piecewise-constant trees | None (linear) |
| Training cost | $O(n^3)$ exact GP (capped at 5000) | $O(T^2 D)$ per layer | $O(n b d M)$ | $O(n p^2)$ (VIF) |
| Interpretability | Kernel structure, ARD lengthscales | Low | Feature importance (SHAP) | Coefficients, selected features |
| Hyperparameter tuning | Marginal likelihood | CV epoch count | Optional Optuna CV | Fixed pipeline thresholds |
